Design notes:
  - Establishment is now measured where it happens: route() timestamps every routed reply, and Call rejects a reply whose timestamp is after the context deadline (previously a late reply could win the select race, and the runner compensated with a return-time check that also swallowed timely results delayed by cleanup). The runner's post-hoc rewrite is deleted; a clean result now means every response was routed before the deadline regardless of cleanup duration.
  - die() invokes the abort hook exactly once (deadOnce), so terminal failure, explicit Close, and cancellation all unblock owned readers/writers; the previously advertised-but-unimplemented Close abort is now real. The abandoned sendRejection writer is released by that same abort rather than holding the write lock forever.
  - Cleanup runs against one absolute deadline: finish() now receives shutdown's deadline instead of granting a fresh full budget; an unjoined drain or unreaped child surfaces ErrCleanupIncomplete instead of a success result.
  - Honest limitation: the double-budget defect was structural and is fixed by construction, but it was not runtime-distinguishable on this platform in the old code (closing the read end always wakes the drain goroutine), so the end-to-end budget test guards the bound rather than reproducing the old worst case.
Fixtures: unchanged.
Findings and bounded remediation: the audit's "reentrant-close deadlock" concern was re-verified as refuted (die is sync.Once-guarded; abort is idempotent via child closeOnce). Descendant policy resolved per the qualified ownership boundary and documented in code: descendants surviving a cleanly exiting child are preserved (membership in the private group does not prove disposability — a provider-managed shared leader can be a descendant); the group SIGKILL is reached only when the direct child we started refuses to exit.
Compatibility/platform limitations: none introduced; unix-only escalation path unchanged.
